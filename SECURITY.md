# Security policy

## Reporting a vulnerability

Please **do not open a public issue** for a security problem.

Use GitHub's private reporting instead: **Security → Advisories → Report a vulnerability**
on this repository. That opens a private thread with the maintainer and keeps the details
out of public view until a fix is ready.

Useful details: the affected route or screen, the steps to reproduce, and what an attacker
could gain. Please avoid testing against the live deployment with other people's accounts.

## Scope

In scope: the web app and its API routes under `apps/web`, the Expo client under `apps/mobile`,
and anything that could expose another account's data, bypass authentication, or corrupt the
XP ledger.

Out of scope: findings that require a compromised device or browser, missing hardening headers
with no demonstrated impact, and reports generated by automated scanners without a proof of concept.

## Supported versions

Only the current `main` branch is supported. Fixes land there; there are no maintained release
branches yet.

## What the project already does

- Firebase ID tokens are verified against Google's JWKS (issuer, audience, `auth_time`), and the
  user id always comes from the token, never from the request body.
- Unverified email accounts can reach the verification endpoint only.
- Every state write is re-validated, content-limited and quota-checked server-side.
- Server secrets live in the hosting environment; the repository contains only `.env.example`.
